# Ceramic CAD to 3D

Automation acceptance: given reviewed shape, dimensions, materials and placement,
generate and revise through the maintained entrypoint without a new script for
each project or part count. New inputs exercise shared contracts and generators.
An isolated hardcoded experiment proves feasibility only, not general support;
retain its findings and return to the current integration TODO. Completion needs
actual shared-path execution and affected regression checks.

Target output: a generated project-detail body/page containing CAD→wire→clay→glaze→photos, plus its source-derived assets. The host site supplies navigation, project listing, URL registration and deployment. Current single rotational outputs are review candidates; this is not yet a complete general-purpose release.

Read the [pipeline and decision status](references/pipeline.md) before starting or extending a project. This is a living skill: move adopted decisions into its active profile and consuming generator with a meaningful output check; keep rejected experiments out of the active path. The documented 00–11 pipeline is the target workflow, while the commands below are the currently supported subset. Do not infer implementation from a checklist or a passing PoC alone.

Use the supported Linux x86_64 / Python 3.14.3 environment. Run `python3 scripts/run.py environment --setup` from this skill to create its local `.venv`, install [requirements-lock.txt](requirements-lock.txt), and install npm dependencies using the pinned Docker image. Then use `.venv/bin/python scripts/run.py environment` to check versions and that interpreter for project commands. See [environment contract](references/pipeline.md#reproducible-execution-environment). Resolve `scripts/run.py` relative to this skill and pass `--workspace /path/to/project` for `new`, `resume`, `revise`, `verify`, and `rollback`. Read [input contract](references/input.md) before preparing a P1 intake, answer, or manual CAD config. The entrypoint stores each project under `.poc/jomul-project-assets-workspaces/<NN>-<slug>/` with a state file and review log; snapshots are separate per project.

For `new --intake`, inspect the sketch itself and create a reviewed P1 extraction with source regions, uncertainty, shape features, and questions. For each rotational part, also provide a reviewed outer profile. The CLI checks the source sketch hash, stores the P1 extraction and question state in the project, adds missing exact-dimension and clay/glaze questions, and reports pending fields in `intake/summary.json`. Ask only those unresolved questions. Save each real user reply with its message reference and verbatim text as an answer JSON; call `resume --answer` for one or more replies. If the answered dimensions require a corrected silhouette, supply a separately reviewed `resume --profile PART=FILE` update. The CLI validates answer IDs, ranges, fields, and evidence, then assembles dimension/material/config JSON and builds CAD when all CAD-blocking fields and dimensions are available. Preserve exact ranges as ranges until the user selects a value. Never label a sketch observation or illustrative shrinkage as a manufacturing confirmation. A P1 extraction is agent-reviewed input; this CLI does not interpret image pixels independently. The old `new/resume --config` path remains for already reviewed manual CAD inputs. `resume` without new input reports the pending state. A P1 project cannot silently replace derived CAD with a manual config. Correcting an already confirmed answer needs a reviewed intake revision; do not overwrite its original evidence. `revise` records feedback and snapshots the project before replacing CAD inputs; `verify` checks source and output hashes plus the CAD geometry contract; `rollback` restores a named project snapshot without touching another project.

A `handled-vessel` P1 intake may omit the P2 profile: it preserves questions and real answers and can be verified while CAD is blocked. Keep handle and body under one part; never route the body alone through rotational CAD as the complete mug. Attach a separately reviewed body `resume --profile PART=FILE` and [handle path](references/handled-vessel.md) `resume --handle PART=FILE`; these are hashed in P1 without clearing unanswered CAD questions. Once all blocking fields have real answers, the P1 route assembles the same handled config and builds it. A manual `--config` uses that same renderer for a separate provisional comparison workspace and cannot overwrite a P1 project. If the user authorizes provisional handle depth or section, archive the verbatim reply as a deferred P1 answer and continue in the isolated manual comparison workspace; do not label the provisional numbers user-confirmed. Inspect the GLB from the side and rear before accepting a smooth handle, because numeric front placement and valid fusion do not prove a smooth join. For photo-backed smooth C handles, use the shared shape-preserving path in the handle contract for CAD and STEP, check that the sampled lower path does not reverse or dip below its attachment, and use CAD-sourced 3D guide lines for the browser wire stage; raw GLB tessellation edges are not the intended wire drawing. With build123d, a handled config produces a CAD guide plus one joined STEP/GLB solid. The solid path checks joint volume, open cavity, STEP reimport, GLB bounds, and numeric front-view placement against the sheet. The one-sheet technical SVG supports nonempty part lists, preserving the original one/two-part layouts and adding complete per-part panels for larger lists in desktop, mobile, and mobile-short layouts; short landscape reuses desktop. Each sheet has part-specific `frontBox` metadata for later CAD-to-wire placement. Keep the user-selected visual reference in `assets/accepted-profile.json`; the selected fixture hashes protect the moon and bowl examples only. New projects must derive their own sheet and `frontBox` from their inputs.

For a CAD-ready single `handled-vessel` with a verified GLB, `motion-preview PROJECT --motion FILE` builds a local CAD→wire→clay axis-motion review. The motion JSON must contain `schemaVersion: 1`, `status` (`reviewed-provisional` or `user-confirmed`), provenance, `tiltDirection`, `tiltDegrees`, `bodySpinDegrees`, and `axisPrecessionDegrees`; see [motion input contract](references/input.md#motion-input). The command reads `motion.axisRig` from the accepted design profile, uses the shared axis component and the project’s own CAD/GLB, then runs the four-viewport browser gate before recording a preview. `verify` checks the preview and browser report hashes; a CAD rebuild invalidates the old preview. Docker and the skill-local locked npm dependencies are required; the pinned image supplies Chrome and runs an isolated Vite server. This is a motion review stage, not a full project page; rotational motion, multi-part page assembly, glaze and the final-photo handoff within that preview are still unsupported.

For project-page rendering, use the accepted moon page axis hierarchy and the axis-motion decision in [selection.json](selection.json): the vessel and its CAD-sourced wire turn together around the vessel axis while that tilted axis changes azimuth through 360°. Camera-only 180° orbit belongs to side/rear shape inspection, not the project motion. The moon right 14° and 390° body turn are comparison values until the new project’s direction, angle, and pacing are reviewed. Verify the handle stays in frame at intermediate angles on desktop and mobile. Handled full-page candidates reuse this same motion module; see the handled review contract below.

Use `status PROJECT [--changed cad|motion|gallery]` to inspect current stage readiness and downstream impact without mutating the workspace. Read the execution-state contract in [pipeline](references/pipeline.md#execution-state-contract). Gallery preparation can run before CAD is ready.

Before applying reviewed CAD changes, `status PROJECT --config FILE` shows the selective rebuild plan. `resume/revise --config` uses that plan; legacy projects rebuild once to record fingerprints. After CAD changes, previously reviewed motion is automatically rebuilt and browser-gated. A failed motion job preserves CAD and input; `resume PROJECT` retries once. Projects without reviewed motion input still require `motion-preview --motion FILE`.

Browser motion and gallery checks remain separately executed evidence; see [verification scope](references/pipeline.md#decision-linked-verification).

For a new **single rotational** page candidate, add `--review REVIEW.json` to `selected-page --cad-project PROJECT_DIR --output DIR`. Read the new single-page review contract in [pipeline](references/pipeline.md#new-single-page-review). This mode regenerates geometry, sheet, materials, motion inputs and reviewed photos using the shared scene renderer. An explicit empty photo list ends at the fully glazed vessel; photo-bearing pages retain the selected exit/gallery transition. It requires height 30–300 mm and diameter/height 0.5–3, and runs four-viewport technical checks before publication. It does not mark the new appearance adopted. Registered page reviews support automatic rebuilding as described below; the two-part contract uses a separate review schema.

For project-managed pages, use `page-review PROJECT --review FILE` to register one of the supported selected-page review schemas. The same generator/browser gate produces an immutable `page-revisions/<id>/` output; `status` reports the current output path. `resume` reuses unchanged verified output, rebuilds changed CAD/photo/review/runtime dependencies, and retries a failed/interrupted page job once. CAD revisions and `gallery --photos` on a registered project also trigger the page job; the latter replaces the page's reviewed photo-list reference. Review JSON is preserved in state; referenced photo metadata/files must remain in the workspace. Failed generation retains the previous page and requested review, while reporting failure. Prior revisions are kept for inspection/rollback. Legacy `page --scene` stays withdrawn and its inputs are never migrated automatically. CAD uses a nonempty parts list; multiple pages require at least two distinct rotational parts and a complete reviewed appearance/motion record for every part, in matching order. For larger lists the CAD sheet grows by panels; this does not guarantee readable full-sheet labels at every viewport. Preserve source sheet dimensions and per-part frontBoxes. Current evidence covers CAD 3/5 parts, intake 5 parts, and a synthetic three-part page through 48 browser checks; the existing two-part page also passes 48 checks. Larger page counts and practical display limits still require browser evidence. Arbitrary assembly, wide shallow plate proportions and exterior height-based glaze masks remain separate pending work.

### Adopted sequential-drop finish

The user adopted revision `6e815f1a65e141b794bb2ca295600804` for this motion.
For new sequential direct-drop reviews, use `assembly.preset: "gentle-staggered"`
unless the user explicitly requests a different style. The active profile
`assembly.gentleStaggeredDrop` supplies soft-spin and overlapping descent and
preserves the reviewed three-part timing reference. The generator rejects
conflicting settings and excessive landing gaps between upper pieces (gap ≤ 20%
of the shorter fall interval). Keep rotation through landing and a gentle stop;
reduce gaps by overlapping falls, not by making each fall abrupt. Review drop
heights, overall scroll duration and collision clearance for new shapes/counts.
This adopts the motion, not specimen materials, arbitrary layouts or physical
simulation. Existing generated revisions are not bulk regenerated.

For feature partial/two-layer pages, read [feature coating input](references/input.md#feature-partial-and-two-layer-coatings). Keep ordered application evidence separate from fired appearance. Exterior identity comes from the pre-hollow CAD boundary, excludes hollow inner walls and the opening rim, and includes the underside. Do not use a radial-vessel mask for nonrotational geometry. This is the existing two-pass preview model, not arbitrary layer counts or a firing simulation.

For reviewed external CAD, use `construction: imported` with one base `kind: step` feature as specified in [STEP input](references/input.md#reviewed-step-input). Preserve the source bytes/hash, declared mm bounds and solid/hollow intent. The project archives STEP dependencies and uses the existing drawing, motion, page and revision path; do not substitute a similar generated shape. Import does not infer missing dimensions, material or manufacturing validity.
